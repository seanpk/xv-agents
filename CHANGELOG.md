# Changelog

Every change to a brief, a may-not list, a standing order, or a check an agent is judged by, with who agreed it. A change to an agent is Decide from evidence: two people, written down short. A version line without two names is a draft.

## Unreleased

- The slice skill's read-back is the full scenario and its "may ignore" lines, written in the message to the person, not only a path to a file. This changes a skill; Sean decided it, solo (#95).

- A stop keeps the decision, not only the answer. `xv record offer` puts the options, each with the `settled` text it would record and whether it amends the scenario, and the watch's pick, on the open stop; `xv record answer` takes `--pick`, `--settled`, `--new-info`, `--cause`, `--why` and `--bundle`, and the stop keeps the person's words, the pick, `settled`, `new_info`, `cause`, a budget change and the bundle. `xv prompt` gives the next agent `settled`, not the raw answer. `xv decisions [--since <date>]` counts stops per order, picks taken, `new_info` none and causes. The watch's brief uses `offer` and stops writing "Settled at" paragraphs into the scenario; an amending decision goes through `xv slice amend`. The scenario brief says to write the form `settled` names (a lint rule, a script) or stop, not swap in a test. A step that stops or ends with no report keeps `next` on that step. `xv record answer --resume` needs `--next`, so every answer says where the slice goes; `--settled` is required only when `--next` sends the work back (to the step that stopped or an earlier one) or the pick is `other`. The decision record and the `decisions` list keep `settled` with the person's words. A stop seated `originator` may be answered by a name other than `set_by`. This changes two briefs and a standing order's effect; Sean decided it, solo (#80, #62, #42, #73). It moves no position on xtremevibing.com.

- Some stops need no `--settled` when the answer moves the slice forward. A stop raised before its work started takes any `--next` without it: `setup_failed` saved at step `setup`, a prototype stop other than `prototypes_ready`, and a `budget_spent` stop raised before its step ran, answered with `--next` that step. `setup_failed` raised after the scenario step, the `prototypes_ready` pick and the `budget_spent` stop raised after the maker left the suite red keep the rule. `xv record stop` takes `--step`. This changes the watch's brief and a check; Sean decided it, solo (#82). It moves no position on xtremevibing.com.

- A red that leaves part of the scenario untested stops before the maker. The scenario agent's report gains `covers` (each item the scenario names, with its test) and `not_covered` (each item it did not cover, with why); an item in `not_covered` stops the slice for the person who set the work going. After the scenario step a check, `wall.red_gaps`, lists every flag and `xv` command in backticks in the scenario, amendments included, that no red file has (a command's words must appear together, in order), and stops the slice the same way. The check never passes on input it cannot read: a record with no `## Scenario` heading, or a report whose `covers` or `not_covered` is missing, not a list, or (for `covers`) empty or naming no test, stops the slice too. So does a `covers` item whose test is in no red file; the test must match a whole test name, not part of a longer one. This changes the scenario brief and adds a check; Sean decided it, solo (#64, retro candidate 1 of 2026-10-29). It moves no position on xtremevibing.com.

## 0.3.1, 2026-10-28

Three changes from this repo's own slices, each run by the watch and decided by Sean solo: the wall reads old tests in a red file (#53), a prototype that runs out of budget comes back to a person (#55), and `xv init --no-try`, which the suite uses to run in about 80 seconds instead of 130 (#38). The last one changes no brief, standing order or check, so it has no line below.

- The wall sees old tests in a red file. A red file that existed at the base is covered only for the tests the slice added: a changed or deleted line in it is `unrecorded` in the CI form (`xv wall check --base`) unless a recorded move names the file. A red file new in the slice is covered whole, as before. A blank, comment or import line changed or removed there is not a move; import lines are matched per file type in one table (`IMPORT_MATCHERS` in `scripts/wall.py`), a line that only contains the word `require` counts, and a file type with no matchers skips only blank and comment lines. The slice's own run makes the same comparison after the scenario step and stops for the person who set the work going (`unrecorded_move`) before the maker runs; when that check cannot run (no `base` in the record, or the wall module cannot load) the slice stops with `setup_failed` instead of passing. This changes a check; Sean decided it, solo ([#53](https://github.com/seanpk/xv-agents/issues/53)).
- A prototype that runs out of budget comes back to a person. When a variant has spent its own budget, the others still run, and then `prototype_budget_spent` stops for the person who set the work going, naming each variant that ran out and what it spent. They raise that variant's budget and run `xv prototype start` again, pick a variant that finished, or pick `none`; a variant that ran out cannot be picked, and when all three ran out `none` is the only pick. A variant that passes its budget during its run counts as ran out too. A variant has finished only when it has a recording and did not run out: a second start runs every variant that has not finished, on its raised budget, and keeps the finished ones with their worktrees, recordings and side-by-side rows; a start with a new `--axis` keeps none. The stop words a run-out during the run apart from a variant that was not run, says to answer it before starting again, and says a budget raise is answered by the person who set the work going alone while a pick, `none` included, is for two people unless the repo runs solo. `prototype_budgets_not_set` is raised by the rule in `scripts/orders.py` before any variant runs; `xv prototype start` no longer words its own copy. This changes standing orders; Sean decided it, solo ([#55](https://github.com/seanpk/xv-agents/issues/55)).

## 0.3.0, 2026-10-27

The first changes from slices: this repo's own, each run by the watch and decided by Sean solo, and the first trial slices on a large existing Rails and TypeScript app, reported in issues. Built by Claude (Opus 5.5, with Haiku, Sonnet and Opus agents in each slice) on Sean Kennedy's direction of 2026-10-25 to 2026-10-27. Every brief, check and standing order change below was decided by one person; none has yet been agreed by two.

- A red that runs several test runners fails when any of them fails. The scenario brief says to join the runners in `red.command` with `&&`, never `;`, `||`, `|`, `&` or a new line, and a command joined with a top-level `;`, `||`, `|`, `&` or newline (outside quotes) is not run and is not kept as the slice's red: the scenario step ends in the `scenario_stopped` stop for the person who set the work going, naming the command and saying to use `&&`, and `next` stays `scenario`, so answering the stop sends the work back to the scenario agent. This changes a brief and a check; Sean decided it, solo ([#51](https://github.com/seanpk/xv-agents/issues/51)).
- The budget caps the whole slice, red or green. Before each step, the watch compares the slice's spend, every step but the prototypes, with the budget. A Claude step gets `--max-budget-usd` set to the dollars left and `--max-turns` set to the turns left. When dollars, tokens or turns are used up, the step does not run, and `budget_spent` stops for the person who set the budget, whatever the suite says; `session` steps get the same check. The after-maker check and the retro's overrun count use the same count. A prototype slice takes one budget per variant, `xv record set <id> prototype_budgets '{"a": {...}, "b": {...}, "c": {...}}' --by <name>`, free to differ: each variant is capped at its own budget less its own spend, a variant that has spent it stops alone and the log and the side-by-side file say so, and `prototype_budgets_not_set` stops the slice until they are set. The watch's stop table says so. This changes standing orders and a brief; Sean decided it, solo ([#34](https://github.com/seanpk/xv-agents/issues/34), [#36](https://github.com/seanpk/xv-agents/issues/36)).
- A scenario run after the maker no longer costs the person needless stops. Its report gives the whole red, every red file and one command for all of them (scenario brief step 7), and the record adds its files to `red.files` instead of replacing them. The slice keeps the commit from before the maker's first run (`pre_maker_commit`, saved once), and the after-maker check runs the red against it, in a temporary worktree that runs `worktrees.setup` first; a failing setup there is the `setup_failed` stop, raised by `orders`. A `--slice-only` move keeps its marker only for a test on the record's `slice_only` list, matched by file and test name exactly; any other move fires `accept_moves`. This changes a brief, a check and a standing order; Sean decided it, solo ([#44](https://github.com/seanpk/xv-agents/issues/44)).
- `xv prompt` gives each agent a list of the shell commands it may run, read from the Bash rules in that agent's own `--allowedTools` in `.xv/config.yml` (its line, or the default line), with three cautions: chain commands only when every part is a listed form, add no flags in front of a listed form, and pipe to no unlisted program. A rule in the `Bash(cmd:*)` or `Bash(cmd *)` form is listed as the plain command. A line with no `--allowedTools`, or a harness other than Claude Code, gets no list. This changes what every agent is given; Sean decided it, solo ([#48](https://github.com/seanpk/xv-agents/issues/48)).
- `xv boundary` tries the importing file's own folder first only when that folder has no `__init__.py`, so a bare import inside a package resolves the way Python does and flat scripts are unchanged. This changes a check the guardian reads; Sean decided it, solo ([#26](https://github.com/seanpk/xv-agents/issues/26)). This changes one of the guardian's checks; Sean decided it, solo ([#26](https://github.com/seanpk/xv-agents/issues/26)).
- Tests a slice leaves behind fit the layout and do not go stale. The scenario brief asks for new tests in the existing test file for the code under test, and a new file only when none exists. The scenario agent reports `slice_only` tests, ones that only prove the slice did its job, and the record keeps them. After green, the cleaner removes each one as a recorded move marked `--slice-only`, unless it finds a reason to keep it, and `accept_moves` does not fire for those moves. The packet lists the removed tests on one line and names each kept one with the reason. `xv record move` takes `--to <path>`, `--deleted` (the whole file is gone) and `--slice-only`, and a move of a red file updates `red.files` and `red.command`, including a bare module name; `red.command` is null when no red file is left. This changes three briefs, the packet template and a standing order; Sean decided it, solo ([#17](https://github.com/seanpk/xv-agents/issues/17)).
- A spend item's `tokens`, and so the budget's token cap, the forecast, new estimation guide rows and the retro's forecast check, count input, output and cache-write tokens, not cache reads; the four raw counts are still kept. One count everywhere. This changes a standing order's measure; Sean decided it, solo ([#28](https://github.com/seanpk/xv-agents/issues/28)).
- `xv slice new` starts the branch from `--base <ref>`, else `worktrees.base`, else the remote's default branch (`origin/HEAD`), else HEAD. `worktrees:` in `.xv/config.yml` may be a block with `setup` and `teardown` commands; setup runs in the new worktree before the forecaster, and a non-zero exit is a new `setup_failed` stop for the person who set the work going, quoting the command's last lines. Both read the worktree's own config, from the base, and run under `tests.timeout`; a timed-out command keeps its last output. `{worktree}` is substituted already shell-quoted. Teardown runs when the slice closes, and `xv check` lists both. `xv slice new` refuses a base with no committed `.xv/config.yml`, `pitch.md` and `picture.md`, and says to push `.xv/` or pass `--base HEAD`. This adds a stop; Sean decided it, solo ([#27](https://github.com/seanpk/xv-agents/issues/27)).
- The maker's and the cleaner's briefs say green means the suite command exited 0, and the `cleaner_broke_suite` and budget stops quote the first failing step of the whole suite output, kept in the record before its 800-character tail is cut. Two briefs and two stop questions changed; Sean decided it, solo ([#19](https://github.com/seanpk/xv-agents/issues/19)).
- After a person answers a stop, `xv prompt` gives the next agent that answer word for word, under its own heading. `xv slice amend <id> --by <name> --scenario-file <file>` adds to a slice's scenario with the date and the name, clears the red, and sends the slice back to the scenario agent. This changes what every agent is given; Sean decided it, solo ([#18](https://github.com/seanpk/xv-agents/issues/18)).
- `xv init` writes a starter `--allowedTools` list on each Claude Code agent line: read-only shell and git commands, `git rm`, `git mv`, `xv record move`, and one rule per part of the test command it chose, never stopping at the program name, so a single test file runs as well as the suite. The guardian also gets `xv wall diff`, `xv boundary` and `xv packet lint`. `xv prompt` now names the `xv` command as plain `xv` when it is on the PATH, so these rules match what agents run. The `xv-init` brief tells the person to keep the test rules in step with `tests.command`. Sean decided it, solo ([#16](https://github.com/seanpk/xv-agents/issues/16)).
- `xv promote draft` cuts a title at a word boundary, writes "Applies to: any" when no `--applies-to` is given, names the draft file with one date, and ends the draft with `promote.attribution` when it is set. The `xv-init` brief names the new setting; Sean decided it, solo ([#13](https://github.com/seanpk/xv-agents/issues/13)).
- `xv boundary` resolves a bare Python import from the importing file's own folder, then the repo root, then each source root, so a `src/` layout and flat scripts that import each other by name get their edges. This changes one of the guardian's checks; Sean decided it, solo ([#12](https://github.com/seanpk/xv-agents/issues/12)).
- The `diff_growing` stop and `limits.max_diff_lines` count only files outside `.xv/`, so a packet or boundary file the guardian writes no longer makes the diff look like it grew. This changes a standing order's measure; Sean decided it, solo ([#24](https://github.com/seanpk/xv-agents/issues/24)).
- `xv init` runs the test command it guessed once and reports `passed`, `failed` (with the tail) or `timed out`. It also gives the module count and lists folders that git tracks and that look like fixtures. The `xv-init` brief tells the agent to show each to the person, to ask for a command when none was guessed, and not to fix a failing command itself. Sean decided it, solo ([#14](https://github.com/seanpk/xv-agents/issues/14)).

## 0.2.0, 2026-10-24

The first changes from use: one `xv init --trial` on a large existing Rails app, reported in [#6](https://github.com/seanpk/xv-agents/issues/6). Built by Claude (Opus 5.5, with Sonnet subagents) on Sean Kennedy's direction of 2026-10-24. The change to the `xv-init` brief has not yet been agreed by two people.

- `failing_tests` reads RSpec, Jasmine, vitest, minitest, mocha, cargo and Playwright failures, so the record names them when the suite is red ([#5](https://github.com/seanpk/xv-agents/issues/5)).
- `xv boundary` names a module under a source root other than `.` with the root, `app/controllers` and `app/javascript/controllers` instead of both `controllers`, so imports between them are edges. This renames modules in any repo with such roots; accepted, since v0.1.0 has one known user ([#4](https://github.com/seanpk/xv-agents/issues/4)).
- `xv init` checks every test marker, not the first: a Rails app with a `package.json` gets `bundle exec rspec` (or `rake test`), the test paths of every runner, and a `runners` list in its output when there is more than one.
- `xv init` proposes `app`, `lib` and `app/javascript` as the source roots of a Rails layout.
- `.xv/config.yml` accepts a flow list or map split across lines.
- `xv init` sets `promote.include_name: false` when GitHub says the repo is private.
- `tests.command` runs with `XV_BASE` (the slice's base commit) and `XV_SLICE` (its id) in the environment, for a script that picks suites from the changed files.
- A trial whose `.xv/` is its own git repo no longer copies that repo into each slice's worktree.
- `xv init --trial --repo` makes `.xv/` its own repo for the trial; `xv init --adopt` refuses while it has uncommitted changes, then moves it to `<git dir>/xv-trial.git` and says where ([#6](https://github.com/seanpk/xv-agents/issues/6)).

A draft change to the `xv-init` brief and the outsider brief, by Claude (Opus 5.5) on Sean Kennedy's direction of 2026-10-24, from the first `xv init` on a large existing app ([#6](https://github.com/seanpk/xv-agents/issues/6)). Not yet agreed by two people.

- `defaults/pitch.md`: the one-sentence pitch under the title, then "The page" with "Why it exists", "Who uses it" and "Who it is not for, and what it will never do". `xv-init` asks for the sentence on its own and holds the person to one sentence ([#3](https://github.com/seanpk/xv-agents/issues/3)).
- `xv-init` checks the setup with the person before the outsider read: which test runners to use, a script for a suite too big to run in minutes, the source roots against `.xv/boundary-all.md`, and the trial choices (`--trial`, `--trial --repo`, `--adopt`).
- `xv-init` says what the picture is for, who the outsider is, which agents load the picture, and what "in motion" is for. It drafts the binding decisions from the repo's own agent files and docs for the person to cut and add to.
- The outsider read uses the repo's docs (`docs/`, AGENTS.md, CLAUDE.md, generated architecture docs) as claims to check, and lists where the code and the docs disagree.
- The first packet raises a gap only when settling it would change what a slice may do. Supporting surfaces go on one "Noted, not raised" line.
- `xv-init` ends with a review of the init: the questions the person asked, the work outside the skill, the wall-clock time, drafted as learnings through `xv-promote` and posted only with the person's approval.
