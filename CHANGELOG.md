# Changelog

Every change to a brief, a may-not list, a standing order, or a check an agent is judged by, with who agreed it. A change to an agent is Decide from evidence: two people, written down short. A version line without two names is a draft.

## 0.3.1, 2026-10-28

Three changes from this repo's own slices, each run by the watch and decided by Sean solo: the wall reads old tests in a red file (#53), a prototype that runs out of budget comes back to a person (#55), and `xv init --no-try`, which the suite uses to run in about 80 seconds instead of 130 (#38). The last one changes no brief, standing order or check, so it has no line below.

- The wall sees old tests in a red file. A red file that existed at the base is covered only for the tests the slice added: a changed or deleted line in it is `unrecorded` in the CI form (`xv wall check --base`) unless a recorded move names the file. A red file new in the slice is covered whole, as before. A blank, comment or import line changed or removed there is not a move; import lines are matched per file type in one table (`IMPORT_MATCHERS` in `scripts/wall.py`), a line that only contains the word `require` counts, and a file type with no matchers skips only blank and comment lines. This changes a check; Sean decided it, solo ([#53](https://github.com/seanpk/xv-agents/issues/53)).
- A prototype that runs out of budget comes back to a person. This changes standing orders; Sean decided it, solo ([#55](https://github.com/seanpk/xv-agents/issues/55)).

## 0.3.0, 2026-10-27

The first changes from slices: this repo's own, each run by the watch and decided by Sean solo, and the first trial slices on a large existing Rails and TypeScript app, reported in issues. Built by Claude (Opus 5.5, with Haiku, Sonnet and Opus agents in each slice) on Sean Kennedy's direction of 2026-10-25 to 2026-10-27. Every brief, check and standing order change below was decided by one person; none has yet been agreed by two.

- A red that runs several test runners fails when any of them fails. The scenario brief says to join the runners in `red.command` with `&&`, never `;`, `||`, `|`, `&` or a new line, and a command joined with a top-level `;`, `||`, `|`, `&` or newline (outside quotes) is not run and is not kept as the slice's red: the scenario step ends in the `scenario_stopped` stop for the person who set the work going, naming the command and saying to use `&&`, and `next` stays `scenario`, so answering the stop sends the work back to the scenario agent. This changes a brief and a check; Sean decided it, solo ([#51](https://github.com/seanpk/xv-agents/issues/51)).
- The budget caps the whole slice, red or green. Before each step, the watch compares the slice's spend, every step but the prototypes, with the budget. A Claude step gets `--max-budget-usd` set to the dollars left and `--max-turns` set to the turns left. When dollars, tokens or turns are used up, the step does not run, and `budget_spent` stops for the person who set the budget, whatever the suite says; `session` steps get the same check. The after-maker check and the retro's overrun count use the same count. A prototype slice takes one budget per variant, `xv record set <id> prototype_budgets '{"a": {...}, "b": {...}, "c": {...}}' --by <name>`, free to differ: each variant is capped at its own budget less its own spend, a variant that has spent it stops alone and the log and the side-by-side file say so, and `prototype_budgets_not_set` stops the slice until they are set. The watch's stop table says so. This changes standing orders and a brief; Sean decided it, solo ([#34](https://github.com/seanpk/xv-agents/issues/34), [#36](https://github.com/seanpk/xv-agents/issues/36)).
- A scenario run after the maker no longer costs the person needless stops. Its report gives the whole red, every red file and one command for all of them (scenario brief step 7), and the record adds its files to `red.files` instead of replacing them. The slice keeps the commit from before the maker's first run (`pre_maker_commit`, saved once), and the after-maker check runs the red against it, in a temporary worktree that runs `worktrees.setup` first; a failing setup there is the `setup_failed` stop, raised by `orders`. A `--slice-only` move keeps its marker only for a test on the record's `slice_only` list, matched by file and test name exactly; any other move fires `accept_moves`. This changes a brief, a check and a standing order; Sean decided it, solo ([#44](https://github.com/seanpk/xv-agents/issues/44)).
- `xv prompt` gives each agent a list of the shell commands it may run, read from the Bash rules in that agent's own `--allowedTools` in `.xv/config.yml` (its line, or the default line), with three cautions: chain commands only when every part is a listed form, add no flags in front of a listed form, and pipe to no unlisted program. A rule in the `Bash(cmd:*)` or `Bash(cmd *)` form is listed as the plain command. A line with no `--allowedTools`, or a harness other than Claude Code, gets no list. This changes what every agent is given; Sean decided it, solo ([#48](https://github.com/seanpk/xv-agents/issues/48)).
- `xv boundary` tries the importing file's own folder first only when that folder has no `__init__.py`, so a bare import inside a package resolves the way Python does and flat scripts are unchanged. This changes a check the guardian reads; Sean decided it, solo ([#26](https://github.com/seanpk/xv-agents/issues/26)). This changes one of the guardian's checks; Sean decided it, solo ([#26](https://github.com/seanpk/xv-agents/issues/26)).
- Tests a slice leaves behind fit the layout and do not go stale. The scenario brief asks for new tests in the existing test file for the code under test, and a new file only when none exists.
