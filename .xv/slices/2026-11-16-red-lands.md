# A slice from a build sees its own red (#182)

## Scenario

A slice from a build sees its own red.

1. When the red's cherry-pick onto the build aborted on an earlier pass, a later scenario pass lands every commit on the red ref that is not yet on the slice branch, even when that pass makes no new commit. A conflict still stops with `red_conflicts_with_build`.
2. The coverage check and the flags checks read each red file as the red ref has it, not the build's file at the same path.
3. The coverage check finds a test in any red the slice has had, not only in the last pass's `red.files`.
4. A `covered` entry may name an amendment's outcome by its number, as it may an outcome above `### Amended`.
5. A line in CHANGELOG.md.

## May ignore

- a red that conflicts with the build: it still stops
- old slice records
