# A prototype pick can be kept as the build its slice starts from

## Scenario

1. At the "Prototypes ready to pick from" stop, the people may keep the pick as the build: `xv prototype pick <id> --variant a|b|c --by <name>,<name> --scenario-file <file> --keep [--share-build]`. The pick's branch is merged onto the slice branch, the other two prototypes are removed, and the kept one's worktree is removed too; only its branch stays. The record says `build: {kind: kept_pick, ref, variant, commit}`. The slice then runs as one opened with `xv slice new --from`: the red is written blind at the base, must fail there, then runs on the build. (#117)
2. Without `--keep`, the pick works as it does today: all three are thrown away. `--keep` with `none`, `--share-build` without `--keep`, and a kept pick whose branch is gone or adds nothing are refused, and a refusal changes nothing in the record.
3. A build's edits to `.xv/` are dropped, for a kept pick and for `xv slice new --from`. The slice log names each dropped file and the build commit that holds its copy. A file that differs only because the base moved on takes the base's copy and is not named. A kept pick keeps its own `.xv/prototypes/<id>/<v>/` folder.
4. After a pick, `xv prototype start` refuses on the slice, because it is no longer a prototype slice. A pick of `none` stays a prototype slice.
5. `xv close` deletes a kept pick's branch when its commit is in the slice branch. It never deletes a `--from` ref.
6. The `prototypes_ready` stop says the pick may be thrown away or kept. It and `prototype_budget_spent` name each variant that did not finish, with its error.
7. Docs: decision 92 replaces decision 71, as drafted in the explore notes (G5), and 71 gets the one-line marker. The prototype brief loses the two sentences that became untrue, as drafted (G1); it does not tell the agent its version may be kept. The watch skill gives `--keep`. The README stops table and the picture name the kept pick. Docs and briefs that name the practice say Build to find out. The README method block is regenerated with `bin/publish-readme.py`.
