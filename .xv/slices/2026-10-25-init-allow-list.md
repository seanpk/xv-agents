# xv init writes a starter allow list

## Scenario

`xv init` writes a starter `--allowedTools` list into each Claude Code agent line of `.xv/config.yml`: read-only shell and git commands, `git rm`, `git mv`, `xv record move`, and the test command it detected. The forecaster and the guardian get only the read-only part, plus the test command for the guardian. A headless agent with the starter config can run the test command as `xv prompt` gives it. (seanpk/xv-agents#16)

Settled at the guardian's accept stop, 2026-10-26, Sean: the scenario was too narrow. (1) Claude Code matches a rule against each part of a compound command. So split the test command into its parts and give each a rule, as this repo's `.xv/config.yml` does (`Bash(cd tests:*)`, `Bash(python3 -m unittest:*)`), so the red runs too, not only the whole suite. Cover a leading `PYTHONPATH=src` the same way, or say in the skill that the person checks it. (2) The guardian also gets `xv wall diff`, `xv boundary` and `xv packet lint`. (3) The read-only list matches this repo's: add `rg`, `wc`, `sed -n`, `diff`, `git ls-files`, `git grep` and `git rev-parse`. (4) Add a line to `CHANGELOG.md` under Unreleased, Sean, solo.

Settled at the guardian's second accept stop, 2026-10-26, Sean: (1) a rule never stops at the program name. `python3 -m unittest` stays `Bash(python3 -m unittest:*)`; `Bash(python3:*)`, `Bash(go:*)` or `Bash(npm:*)` alone would let an agent run anything, and the guardian would no longer be read-only. Add a test that no starter rule is a bare program name. (2) Rules come only from the test command `xv init` chose, not from every runner it detected or the `tests/` fallback, so a Go repo with a `tests/` folder gets no Python rule. (3) A leading `PYTHONPATH=src` (any `NAME=value`): either give the rest of the command its own rule, or have `skills/xv-init/SKILL.md` tell the person to check that rule by hand. (4) Fix the old comment at `tests/test_init_allow_list.py:97`.
