# A red with several runners fails when any of them fails

## Scenario

A red that runs several test runners fails when any of them fails. The scenario brief says to join the runners in a red command with `&&`, so the first failing runner fails the whole command; it never joins them with `;` or `||`. When a scenario report's `red.command` joins parts with a top-level `;` or `||` (outside quotes), xv does not apply it as the red and does not trust its exit code: the scenario step ends in the `scenario_stopped` stop for the person who set the work going, and the question names the command and says to join the runners with `&&`. Today `scripts/run.py` reads only the shell's exit code (`checks["red_fails"] = code != 0`), which for `a ; b ; c` is `c`'s alone, so a passing last runner hides failing ones. Take the trial's red, `yarn test_shared <specs> ; yarn test_web_components_ci <specs> ; bundle exec rspec <spec>`: it is refused with that question. Joined with `&&`, it fails when the first runner fails. This changes a brief and a check; Sean decided it, solo, and it gets a CHANGELOG line. (seanpk/xv-agents#51)
