# The originator can pair with the watch, and the record keeps it

## Scenario

1. At an open stop or send-back, the originator opens a pairing: `xv pairing start <id> --by <name> --why "<why>"`. It answers the open stop as a pairing and writes a `pairings` entry: who, the session they pair with, why, the start time and the head commit. It refuses a name that is not the originator, and a slice with no open stop or send-back. (#146)
2. While a pairing is open, `xv step` and `xv run` refuse on the slice and name the open pairing. The watch's own session is the person's pair. At the person's direction it writes and changes tests and code, across the scenario, maker and cleaner work. It still may not merge, approve, accept a move or a picture change, set a budget, or answer a stop for the person. Each commit in a pairing starts with `pairing (<name> with <agent>):`.
3. The scenario agent's red stays blind. A test written or changed in a pairing is not blind: the record and the packet say so, and the guardian runs fresh after, so a context that did not pair checks it.
4. `xv pairing end <id> --next maker|cleaner|guardian` closes it; `--next scenario` needs an amendment made since the pairing opened, and `close` is refused. The entry gets the end time, the head commit, the resume step, and the pair session's spend for the time the pairing was open, read from its transcript. The spend counts in the slice's actual and in the budget check. When the spend cannot be read, the log and the packet say so.
5. `xv pairing end` refuses while an old test changed or removed in the pairing has no recorded move, and names each file. A move recorded in a pairing is in the person's name.
6. The packet gets one line per pairing under `## Pairings`: who, with which session, why, the commits, the resume step and the spend.
7. Docs: the watch skill (in a pairing, and only there, the watch does work, at the person's direction), the README, the picture, a decision, and a CHANGELOG line. The word is pairing everywhere.
8. As Sean answered on 2026-11-11: a pairing opens when no transcript is found, and the log says so; the spend window is cut by timestamps; a stop for two people is answered first, unless the repo runs solo; commits without the prefix are listed, not refused; a test a pairing only added to an old file is not a move; the guardian's prompt names the tests that are not blind; `xv slice rebase` and `xv record report` also refuse during a pairing; the pairing's spend row has the step `pairing`; only the pairing window of the watch's session counts (#175). The decision is number 93.
9. `EXPLORE-NOTES.md` at the repo root is not in what merges.
