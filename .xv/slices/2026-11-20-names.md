# The agents have the names the site uses (#168)

## Scenario

The agents have the names the site uses (#168).

1. The scenario agent is the test writer: `skills/test-writer`, the step `test-writer` (`xv step test-writer`, `xv prompt test-writer`, `--next test-writer`), and `agents.test-writer` in `.xv/config.yml`.
2. The guardian is the inspector: `skills/inspector`, the step `inspector`, `agents.inspector` and `agents.inspector_repass`, `xv inspect --base <ref>` in place of `xv guard`, and `ci/github/xv-inspector.yml`.
3. The listener is the field listener: `skills/field-listener`, `agents.field-listener`, and `field_listener:` in `.xv/config.yml`. `xv listen` keeps its name.
4. Under `agents:`, a key that is an agent's name is spelled as that name, with its hyphen (`agents.test-writer`, `agents.field-listener`). Every other config key keeps its underscore (`agents.inspector_repass`, `field_listener:`).
5. The old names still work: `xv step scenario` and `xv step guardian`, `xv guard`, `agents.scenario`, `agents.guardian`, `agents.guardian_repass`, `agents.listener`, `listener:`, the test writer's old scratch file `xv-scenario-scratch-<id>.json`, and a record that holds an old step name in `next`, `checks`, `reports` or `step_start`. Each prints a one-line warning that names the new name and #204.
6. `xv install` links the new skill folders and removes the links it made under the old folder names.
7. In prose (README, docs, the picture, the briefs), the guardian's packet is the inspection report and the listener's packet is the field report. "Packet" stays in commands, file names and record fields, and for a report a decision is made on.
8. No brief or doc opens with "An agent may stop. It may not decide."
9. "boundary picture" is "boundary diagram".
10. A line in CHANGELOG.md.
11. The README's upgrade notes say what an adopter changes.
12. A closed or abandoned slice record reads its old names with no warning. Config keys, commands, arguments and open records still warn once for each old name.
13. The names inside the code follow too: no script, eval, CI file or test names the agents or their steps "scenario", "guardian" or "listener", except where it reads an old name. The internal step is `land-test-writer` and the scratch file is `xv-test-writer-scratch-<id>.json`.
14. The eval ids follow: `inspector-pitch`, `inspector-moves`, `field-report`, `test-writer-defect`, `test-writer-feature` and `test-writer-har`. A past result keeps its old id, and `evals/report.py` shows it on the same row as the new id.
15. `EXPLORE-NOTES.md` is not in the merged tree.
