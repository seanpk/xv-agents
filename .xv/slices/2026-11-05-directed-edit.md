# The watch makes a directed change the person approved: #132

What happened: a change the person had already decided went back through an agent and the guardian, even when it was one line. On slice `2026-11-04-promote-fields`, renaming a test took 18 minutes and $0.87, and deleting a test retired from the wall took 18 minutes and $0.72. The comment on #132 adds evidence from slices B, D, E and I, and three times the watch's own wording drifted, caught each time by an agent or a check.

What should happen:

1. A stop option can carry a directed change: the exact edit, as old text and new text. The person approves that diff, not a description of it. Any edit the watch would have to word itself goes to an agent.
2. Only four kinds are allowed: a line in `CHANGELOG.md`; renaming a test or removing a test, in a file under the wall's `tests.paths`; and a line in a Markdown doc that names what the code already does. Any other edit goes to an agent.
3. When the person picks the option, the watch makes exactly that edit, in its own commit. The commit message names the person who directed it. A test edit is recorded as a move in the person's name.
4. A test rename also updates every record entry that names the test (`slice_only`, `wall_recommendations`, `covers`), in the same commit.
5. After the edit, the suite and `xv orders` run. If the guardian has not run yet, it reviews the edit in its normal pass. If it has run, it does not run again, and the packet gets a line for each edit made after it, naming the edit and who directed it.
6. The watch's brief states the rule: the person approved every word, and the edit changes no behavior. The watch never words a change itself. The four kinds in point 2 are where xv-agents starts. The brief's may-not line changes to match, and `CHANGELOG.md` gets a line for it.

### Amended 2026-11-05 by Sean Kennedy

1. Point 4 changes: a test rename updates the test's name in `slice_only` and `wall_recommendations`, in the same commit. The record keeps no `covers`, so there is nothing to rename there.
2. The surface: `xv record offer` takes `--edit <file> --old <text> --new <text> --kind changelog|test-rename|test-remove|doc`, and these belong to the `--option` before them, as `--settles` does. The offer refuses the edit when the old text is not in the file exactly once, when the kind does not fit the file (`CHANGELOG.md`; a file under the wall's `tests.paths`; another Markdown file), when a rename changes more than the test's name, or when a removal's new text is not empty.
3. `xv record answer --pick <n>` on an option with an edit makes the edit and commits only that file and the record, with a message that names the person as the one who directed it. For a test kind, it records the move in the person's name and renames the test in the record. Then it runs the suite and the standing orders and prints the verdict, as `xv step` does.
4. When the record already has a packet, the answer adds a line to the packet under `## Directed edits after the guardian`: the file, the kind, who directed it, and the commit. `next` does not go back to the guardian.

### Amended 2026-11-05 by Sean Kennedy

1. `scripts/record.py` does not import `run`. The suite run (`run_suite`, with the `shell` and `tests_timeout` helpers it uses) moves to its own module, `scripts/suite.py`, and both `record` and `run` import it.
2. The `doc` kind refuses a file under `.xv/` and any file named `SKILL.md`. Those change only through their own paths, with two people or a `CHANGELOG.md` line.
3. A `changelog` or `doc` edit may span more than one line, but neither its old text nor its new text may hold a blank line. The offer refuses one that does.
4. A `test-rename` or `test-remove` accepts only a test: the old text must declare a test the wall's test names match, not `setUp` or a helper. A `test-remove` must remove the whole test, its declaration and its body; the offer refuses a removal of only part of it.
5. When the standing orders stop after a directed edit, the stop is written to the record as `xv step` writes one, through `record.apply_verdict`, so the person can answer it with `xv record offer` and `xv record answer`.

### Amended 2026-11-05 by Sean Kennedy

1. A `test-remove` of a decorated test removes its decorators with it. The offer refuses a removal whose old text starts at the `def` line while decorators sit above it, so no decorator is left on the next test.
2. When the answer adds a line to the packet after the guardian, the packet goes in the same commit as the edit and the record.
3. The offer refuses a `test-rename` when the old test name also appears elsewhere in the file, outside the line being renamed.
4. The watch's brief and the `CHANGELOG.md` line name every refusal of both amendments, and the new `scripts/suite.py`.
