## Other findings for the person

- **`xv record packet` takes the packet head from the checkout it is run in.**
  - `cmd_packet` sets `root = repo_root()` (`scripts/record.py:910`), but loads the record wherever it is, including the slice's worktree (`scripts/xvlib.py:403-405`).
  - `guardian_facts` then stores `checks["packet_head"] = git(["rev-parse", "HEAD"], root)` (`scripts/record.py:949`).
  - Run from the main checkout, that is main's HEAD, not the slice's. The same `root` makes `data["packet"]` a path relative to main (`scripts/record.py:947`).
  - So the re-pass finds no packet file and quietly becomes a first pass, which is safe but costs a full pass. The step path uses the slice root and is unaffected (`scripts/run.py:1216`).
  - No test runs `xv record packet` from outside the worktree (`tests/test_repass.py:42` runs it with `cwd=self.wt`).
  - The picture says the offer and the answer work in the slice's worktree "wherever they are run from" (`.xv/picture.md:53`), but says nothing about `xv record packet`.
- **Accepted wall recommendations are matched on the test name only.**

  - So an accepted recommendation for `tests/a.py::test_x` is dropped when the next pass names `tests/b.py::test_x`. This is carried forward from the last packet.
